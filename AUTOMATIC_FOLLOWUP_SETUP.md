# Automatic staff and applicant follow-up

Enable HR_FOLLOWUP_AUTO_SELECT=true with HR_FOLLOWUP_EXTENDED_FORMS=true on the existing service. Every workflow cycle scans active recruitment groups 1–8 and the employed group, with complete pagination. Leavers, withdrawals, rejections and the talent pool are excluded from requests. New arrivals in the initial application group are monitored; applicant chasing begins only after acceptance is Yes, the initial pre-employment checks have been sent and the existing supported recruitment stage/group matches. First chasing waits three complete days after the date-only checks-sent or most recent manual-contact dates.

The worker initially scans the full archives of all eleven approved forms, then refreshes incremental receipts each cycle. Salted HMAC keys for normalized names and emails and canonical submission IDs are stored only in the existing private persistent SQLite ledger. Names, email addresses, medical/financial/declaration answers and signature URLs are not stored in this index or logged. Repeated pages, incomplete reads and unidentifiable responses block absence inference for that source. A name OR email match suppresses a new request and asks HR to reconcile identity, completeness and applicable version; it never asserts clearance.

Only supported explicitly missing statuses (or eligible applicant blank history/medical/working-time/dress-code fields) can populate HR follow-up requested. Issued contracts need a sent date and an exact supported role; an unsent contract is an HR action, not an automatically generated offer. Driving declaration requires a Yes driving-licence declaration. Declined and Not Required statuses are preserved. Existing partial histories, payroll encryption, medical renewal, manual evidence, assessments and physical issue tasks remain review routes. References remain on the existing explicit-permission workflow.

Existing requests and received selectors are preserved. Existing campaigns, holds, exhausted campaigns and completed campaigns are never reopened by this selector. It reads the employee/applicant again before writing; identity, stage or status changes cancel the proposal. Any duplicate name/email is held for review. Writes are limited to the requested selector and blank Next Recruitment Action fields. Dedicated approval/clearance fields are unchanged. The existing one initial email plus three 72-hour reminders and exact request-token receipt stopping are reused.

Tick HR automatic follow-up paused to block selection and pause checklist email for the person. Untick it after resolving the issue, then use HR follow-up resume for an existing hold. No control resets send counts or uncertain delivery. Progress endpoints expose counts and safe state only.

Validation: 223 original tests, 5 extended-form tests and 15 new automatic-selection tests passed. These include full archive pagination and restart persistence, privacy, failed source reads, unknown receipt identity, repeated pagination, duplicate identities, fresh-record changes, delayed applicant chasing, manual-contact delays, unchanged campaigns, declined consent, source receipt suppression and pausing an existing campaign.
